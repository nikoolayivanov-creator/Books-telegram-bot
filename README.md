# flibusta-telegram-bot

Telegram-бот для поиска и скачивания книг с [Flibusta](https://flibusta.is).

LLM (GLM-4.5 через z.ai) делает здесь ровно одну вещь: превращает свободный запрос в структуру «автор + название», чтобы OPDS-поиск Flibusta попадал точно. Поиск, ранжирование и скачивание остаются детерминированными и идут без LLM.

## Возможности

- Поиск свободным текстом («конан дойл шерлок»): LLM вытаскивает автора и название.
- Ранжированный список с форматами, размером, числом скачиваний и переводчиком.
- Карточка книги с описанием и кнопками форматов (fb2, epub, mobi, pdf, txt…).
- Скачивание с распаковкой: Flibusta отдаёт fb2/txt/rtf/html в zip, бот достаёт внутренний файл, чтобы читалка его открыла.
- Дневные лимиты на скользящем окне 24 ч: 5 скачиваний, 20 поисков, плюс список безлимитных ID.
- Аналитика в SQLite (`/stats`), кэш поиска в памяти на 6 часов.
- Неблокирующие обработчики и семафоры конкурентности.

## Как используется LLM

На каждый некэшированный поиск — один вызов `parseQuery`, который переводит текст в `{authors, title, series, genre}`. Всё остальное (OPDS-поиск, ранжирование, скачивание) детерминированно. Если LLM упал или таймаутит за 15 секунд, бот откатывается к поиску по сырому названию. Thinking выключен ради скорости, а кэшированные запросы не делают ни одного вызова LLM.

## Требования

- Node 20 (проще всего через Docker).
- Токен бота Telegram от @BotFather.
- API-ключ z.ai (https://z.ai).
- Сервер или VPS с Docker.

## Конфигурация

```bash
cp .env.example .env
```

| Переменная | Обяз. | По умолч. | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен @BotFather |
| `ADMIN_IDS` | да | — | Telegram ID админов через запятую, видят `/stats` |
| `ZAI_API_KEY` | да | — | ключ z.ai |
| `ZAI_BASE` | да | — | эндпоинт z.ai, напр. `https://api.z.ai/api/paas/v4` |
| `MODEL` | да | — | модель, напр. `glm-4.5-air` |
| `FLIBUSTA_BASE` | да | — | зеркало Flibusta, напр. `https://flibusta.is` |
| `FLIBUSTA_FALLBACK_BASE` | нет | — | запасное зеркало |
| `ALLOWED_IDS` | нет | (пусто) | whitelist; пусто — бот публичный |
| `UNLIMITED_IDS` | нет | — | ID без дневных лимитов |
| `DOWNLOAD_DAILY_LIMIT` | нет | 5 | скачиваний за 24 ч |
| `SEARCH_DAILY_LIMIT` | нет | 20 | поисков за 24 ч |
| `RATE_LIMIT_PER_MIN` | нет | 20 | запросов в минуту на пользователя |
| `MAX_QUERY_LEN` | нет | 100 | максимальная длина запроса, символов |
| `SEARCH_CACHE_TTL_SEC` | нет | 21600 | TTL кэша поиска |
| `LOG_TTL_DAYS` | нет | — | срок хранения событий, дней |

## Запуск (Docker)

```bash
docker compose up -d --build
docker compose logs -f
```

## Деплой на VPS

В `deploy.sh` укажите `VPS=user@host`, затем:

```bash
./deploy.sh
```

Скрипт синхронизирует код по ssh, соберёт образ и перезапустит контейнер.

## Разработка

```bash
npm install
npm test
npm run build && npm start
```

## Архитектура

- `bot.ts` держит обработчики grammY на long polling, неблокирующие: дорогая работа уходит в фон, очередь апдейтов не копится.
- orchestrator ведёт поиск по цепочке: кэш → разбор LLM → OPDS-поиск → детерминированный ранг → топ-N.
- `search/llm.ts` — клиент z.ai с единственным методом `parseQuery`.
- `search/flibusta.ts` — обёртка над npm-пакетом `flibusta`: OPDS-поиск и нормализация метаданных.
- `download.ts` скачивает книгу во tmpfs и распаковывает zip-обёртку.
- `db.ts` и `analytics.ts` — журнал событий в SQLite и дневные лимиты.

## Правовые аспекты

У книг на Flibusta разный статус авторских прав в зависимости от юрисдикции. Убедитесь, что имеете право скачивать контент в вашей. LLM-провайдер и модель настраиваются, поэтому соблюдайте условия использования выбранного провайдера.
